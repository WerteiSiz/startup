### Проблема

Студенческие скидки существуют, но информация о них **разбросана по десяткам источников**, нет единого окна поиска, а 29% студентов вынуждены экономить на развлечениях и 27% реже едят вне дома — именно из-за отсутствия прозрачных и легкодоступных предложений.

## 🚀 Запуск проекта

### Требования

- Node.js ≥ 18
- Python ≥ 3.10
- pip

### Установка и запуск

```bash
# 1. Клонировать репозиторий
git clone https://github.com/WerteiSiz/startup.git
cd startup

# 2. Запуск Backend (FastAPI)
cd backend
pip install -r requirements.txt
uvicorn main:app --reload --port 8000

# 3. Запуск Frontend (Vue) — в новом терминале
cd ../frontend
npm install
npm run dev
```

После запуска:
- **Frontend:** `http://localhost:5173`
- **Backend API:** `http://localhost:8000`
- **Swagger docs:** `http://localhost:8000/docs`

> ⚠️ Если структура папок отличается — смотри соответствующую неделю в репозитории (`06-week`, `08-week`, `10-week`).

## 🗺 Ключевой пользовательский сценарий (End-to-End)

**Цель:** студент находит подходящую скидку и использует её

```
1. Студент открывает платформу (лендинг / главная страница)
2. Регистрируется или входит в аккаунт
3. Выбирает категорию скидок (еда / кино / музеи / ТЦ / доставка)
4. Просматривает список актуальных предложений
5. Фильтрует по геолокации или названию
6. Открывает карточку скидки — видит условия, адрес, срок действия
7. Получает промокод или инструкцию по активации
8. ✅ Результат: скидка применена, студент сэкономил
```

**Альтернативный сценарий (скидка не найдена):**
```
1. Студент вводит запрос / применяет фильтры
2. Результаты пустые — отображается empty state с подсказкой
3. Предлагаются похожие категории или сброс фильтров
4. Студент корректирует поиск и находит предложение
```

## 📋 Scope: Must / Should / Could

### Must (ядро MVP — без этого сценарий не работает)

| # | Функция |
|---|---|
| 1 | Регистрация и авторизация пользователя |
| 2 | Каталог скидок с карточками (название, описание, условия) |
| 3 | Фильтрация по категории |
| 4 | Страница детальной карточки скидки |
| 5 | Отображение промокода / способа активации |
| 6 | Пустое состояние при отсутствии результатов |
| 7 | Обработка ошибок (неверные данные, сбой сети) |
| 8 | Адаптивный интерфейс (десктоп + мобайл) |

### Should (улучшают ценность, но не критичны для демо)

| # | Функция |
|---|---|
| 1 | Поиск по названию заведения |
| 2 | Фильтр по геолокации / районам Москвы |
| 3 | Сохранение избранных скидок |
| 4 | Уведомление об истечении срока скидки |
| 5 | Личный кабинет с историей просмотров |

### Could (следующие итерации)

- Рейтинг и отзывы на скидки
- Партнёрский кабинет для размещения предложений
- Push-уведомления
- Интеграция с картами (геовиз)
- Реферальная система / амбассадорская программа

---

## ⚠️ Известные ограничения демоверсии

- База скидок заполнена **тестовыми данными** — реальные партнёры не подключены
- Геолокация **не реализована** в текущей версии
- Авторизация через студенческий билет **не верифицируется** (только самодекларация)
- Мобильное приложение отсутствует — только веб-версия
- Уведомления и email-рассылки не настроены
