## О продукте

**StudentPass** — единая цифровая платформа студенческих скидок. Студенты Москвы находят проверенные предложения от кафе, кино, музеев и магазинов за 2 минуты вместо нескольких часов поиска.

## ШАГ 1 · Scope + Definition of Done

### Must / Should / Could

####  Must — ядро MVP (без этого сценарий не проходит)

| # | User Story | Критерий приёмки |
|---|---|---|
| M1 | Как студент, я хочу зарегистрироваться и войти в аккаунт | Форма входа/регистрации работает, токен сессии сохраняется |
| M2 | Как студент, я хочу видеть каталог скидок с карточками | Список отображается с названием, описанием, категорией и сроком |
| M3 | Как студент, я хочу фильтровать скидки по категории | Фильтр применяется мгновенно, список обновляется |
| M4 | Как студент, я хочу открыть карточку скидки и увидеть детали | Страница детали содержит условия, адрес, срок, промокод |
| M5 | Как студент, я хочу получить промокод или инструкцию активации | Промокод отображается / копируется по нажатию кнопки |
| M6 | Как студент, я хочу видеть пустое состояние при отсутствии результатов | Отображается заглушка с подсказкой «Скидки не найдены» |
| M7 | Как студент, я хочу получать понятные сообщения об ошибках | Ошибки авторизации, сети и валидации показываются inline |
| M8 | Как студент, я хочу пользоваться платформой с мобильного | Интерфейс адаптивен на экранах от 375px |

#### 🔶 Should — улучшают ценность, не критичны для демо

| # | User Story |
|---|---|
| S1 | Поиск по названию заведения или скидки |
| S2 | Фильтр по районам Москвы |
| S3 | Сохранение скидок в «Избранное» |
| S4 | Личный кабинет с историей просмотров |
| S5 | Уведомление об истечении срока скидки |

#### 🔷 Could — за рамками блока

- Партнёрский кабинет для размещения скидок
- Push-уведомления о новых предложениях
- Реферальная / амбассадорская программа
- Верификация студенческого билета через API вуза
- Мобильное приложение (PWA / нативное)

###  Альтернативный сценарий — «Скидка не найдена / ошибка фильтра»

| # | Шаг |
|---|---|
| 1 | Студент применяет фильтр «Музеи» |
| 2 | Список возвращает 0 результатов |

| 4 | Предлагается кнопка «Сбросить фильтры» |
| 5 | Студент сбрасывает фильтр → видит полный каталог |
| 6 | Выбирает другую категорию или использует поиск |
| 7 | Находит подходящее предложение → продолжает основной сценарий |

###  Контрольные точки (КТ)

| КТ | Где | Риск | Метрика успеха |
|---|---|---|---|
| КТ 1 | Лендинг / главная | Медленная загрузка → уход | Загрузка < 3 сек |
| КТ 2 | Авторизация | Сбой → пользователь не входит | Успешный login 200 OK |
| КТ 3 | Детальная карточка | Пустые поля → непонятны условия | Все поля заполнены |

| КТ 5 | Результат | Нет подтверждения → пользователь не понимает, сработало ли | Toast «Промокод скопирован» |

## ШАГ 3 · Структура продукта: экраны, модель данных, API

### 🖥 Структура экранов

| Экран | Назначение (шаг сценария) | Ключевые элементы | Состояния | Переход |
|---|---|---|---|---|
| **Лендинг** | Шаг 2 — первое впечатление | Hero-блок, CTA «Зарегистрироваться» | — | → Регистрация |
| **Регистрация / Вход** | Шаг 3–4 | Форма, валидация, кнопка | loading / error / success | → Каталог |
| **Каталог скидок** | Шаг 5–6 | Фильтры по категориям, сетка карточек | loading / empty / error / success | → Детальная |
| **Детальная карточка** | Шаг 7–9 | Фото, описание, условия, адрес, промокод | loading / error | → Каталог |
| **Профиль** | — | Имя, email, кнопка выхода | — | → Каталог |

### 🗃 Модель данных

#### User (Пользователь)
```
id          UUID        PK
name        string      Имя
email       string      Уникальный, для входа
password    string      Хэш (bcrypt)
created_at  datetime
```
*Операции: CREATE (регистрация), READ (профиль), авторизация*

#### Category (Категория скидок)
```
id      UUID    PK
name    string  «Кафе», «Кино», «Музеи», «Магазины», «Доставка»
icon    string  Emoji или URL иконки
```
*Операции: READ (фильтр каталога)*

#### Discount (Скидка)
```
id              UUID        PK
title           string      Название скидки
description     string      Описание условий
partner_name    string      Название заведения
category_id     UUID        FK → Category
discount_value  string      «20%», «2+1», «−500₽»
promo_code      string      Промокод (nullable)
address         string      Адрес заведения
valid_until     date        Срок действия
is_active       boolean     Фильтр устаревших
created_at      datetime
```
*Операции: READ (каталог, детальная), фильтр по category_id*

#### Partner (Партнёр) — заглушка для следующей итерации
```
id       UUID    PK
name     string
contact  string
```

### 🔌 API-контракт (FastAPI endpoints)

| Метод | Путь | Описание | Auth |
|---|---|---|---|
| `POST` | `/auth/register` | Регистрация | — |
| `POST` | `/auth/login` | Вход, возвращает JWT | — |
| `GET` | `/discounts` | Список скидок, `?category_id=` | JWT |
| `GET` | `/discounts/{id}` | Детальная карточка | JWT |
| `GET` | `/categories` | Список категорий | JWT |
| `GET` | `/users/me` | Профиль текущего пользователя | JWT |

## ШАГ 4 · Реализация ядра и первый E2E прогон

### Порядок реализации Must-функций

```
1. Авторизация (M1)           → без неё ничего не работает
2. GET /discounts + каталог (M2, M3) → основа сценария
3. GET /discounts/{id} + детальная (M4) → ключевой экран
4. Промокод (M5)              → финальная точка доставки ценности
5. Empty state (M6)           → защита от пустых данных
6. Ошибки (M7)                → устойчивость
7. Адаптивность (M8)          → мобильный охват
```

### 📝 Протокол первого E2E прогона

| Где сломалось | Что отсутствует | Приоритет |
|---|---|---|
| Экран каталога при медленном соединении | Нет состояния loading (spinner) | Blocker |
| Форма регистрации | Нет валидации формата email | Major |
| Детальная карточка | Поле `address` пустое у тестовых скидок | Major |
| Копирование промокода | Не работает на iOS Safari (clipboard API) | Major |
| Фильтр категорий | Не сбрасывается при переходе назад | Minor |
| Мобильный (375px) | Карточки выходят за границы экрана | Minor |

> После первого прогона: устранены все Blocker и ключевые Major. Minor — в backlog.

## ШАГ 7 · Демо-скрипт и инструкция

### 🎬 Демо-скрипт (2–3 минуты)

**[0:00 – 0:25] Проблема**
> «Вы студент. Вы знаете, что где-то есть скидки — в кафе рядом с кампусом, в кинотеатре, в музее. Но где именно? Telegram-чаты, сайты вузов, листовки — информация везде и нигде одновременно. 29% студентов экономят на развлечениях не потому, что скидок нет, а потому что не могут их быстро найти.»

**[0:25 – 0:45] Решение**
> «StudentPass — это одно место для всех студенческих скидок. Открываешь, выбираешь категорию, получаешь промокод. Всё.»

**[0:45 – 1:45] Демо (live)**
1. Открыть платформу → показать лендинг
2. Зарегистрироваться → войти в каталог
3. Выбрать категорию «Кафе» → показать список
4. Открыть карточку → показать условия и адрес
5. Нажать «Показать промокод» → скопировать

**[1:45 – 2:15] Результат**

### 🚀 Инструкция запуска и использования

#### Системные требования

- Node.js ≥ 18
- Python ≥ 3.10
- pip

#### Установка

```bash
# 1. Клонировать репозиторий
git clone https://github.com/WerteiSiz/startup.git
cd startup/10-week

# 2. Backend (FastAPI)
cd backend
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
# API доступен: http://localhost:8000
# Swagger:      http://localhost:8000/docs

# 3. Frontend (Vue) — в новом терминале
cd ../frontend
npm install
npm run dev
# Приложение:   http://localhost:5173
```

#### Тестовые данные для демо

| Поле | Значение |

> Тестовый аккаунт уже содержит сессию с заполненным каталогом из 8 скидок в 4 категориях.

#### Как пройти ключевой сценарий

1. Открыть `http://localhost:5173`
2. Нажать **«Войти»** → ввести тестовые данные выше
3. В каталоге выбрать категорию **«Кафе и рестораны»**
4. Нажать на любую карточку
5. Нажать **«Показать промокод»** → **«Копировать»**
6. Наблюдать toast-уведомление «Промокод скопирован ✅»
